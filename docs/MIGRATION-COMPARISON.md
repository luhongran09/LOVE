# 原版 Footprint 与 Vue + Gin 版本差异核对

> 本文件是本轮开发前的差异基线。多图回忆、3D、情侣工具及备份迁移等已有后续实现，最新状态见 [迁移开发进度](MIGRATION-PROGRESS.md)。

核对日期：2026-10-22。范围为本仓库原版 `frontend/`、`backend/`、`miniapp/` 与新版 `web/`、`server/`，不代表上游 GitHub 最新版本。

本次是代码与接口核对，不是对原版所有功能逐一部署验收。原版依赖地图密钥、云存储或外部 AI 的能力，实际可用性还取决于配置。标为“未迁移”表示原版存在对应代码，新版没有等价实现；并不表示双方都应补齐或已验证原版无缺陷。

目前新版完成的是双人相册第一阶段，不是原版的全部功能等价迁移。

## 最关键的数据模型差异

原版以 `record` 为单位：一条旅行、美食或情侣回忆，包含共同的标题、日期、地点、描述和 `images[]` 多张照片，并可携带类型、标签、评分和价格等信息。

新版以 `photo` 为单位：一张照片对应一条数据库记录。一批上传 10 张照片会生成 10 条记录，没有独立的“相册／事件／旅行”实体。按月展示和按地点筛选，不等于将照片归入同一段回忆。

这直接影响多图宫格、沉浸式详情、时间轴、统计和旧数据导入。应先明确并补上回忆与照片的关系，再迁移依赖它的表现层。

依据：`frontend/index.html` 中 `renderMosaic`、`viewRecord`；`backend/routes/records.py`；`server/models.go`、`server/database.go`、`server/photos.go`。

## 视觉与交互仍有的差距

- 已沿用深色底色、青蓝渐变、毛玻璃、胶囊入口、顶部导航和照片卡片，但属于重新布局，不是原界面的逐项复刻。
- 新版增加了首页标题区和双人卡片；原版旅行／美食模式切换及对应配色没有恢复。
- 原版最具辨识度的 3D 地球、复古护照、成就墙和工具 Dock，尚无对应新版模块。
- 原版一条回忆中的多图排版、详情照片流、时间轴缩略图条没有迁移，所以照片内容的组织与观看体验仍有明显差异。
- 动态背景只有 CSS 光斑和网格，没有完整迁移粒子背景、成就礼花等动效。
- “城市记忆”“时光轨迹”等新版入口只能代表当前实际的地点分组与照片时间轴，不能据名称判断已实现原版的所有同类能力。

## 当前新版自身还需要补的事项

这些是对当前实现的检查，不应直接当作原版已具备的功能：

1. 列表一次加载全部照片元数据，筛选主要在浏览器完成；缺少服务端分页与面向大量照片的缩略图方案。
2. 两人共享服务端数据已实现，但没有 WebSocket／SSE／轮询自动刷新；另一端通常需要手动刷新才看到变化。
3. ZIP 恢复受 250MB 限制（压缩文件和解压总量），而导出没有按该限制校验。图库较大时可能导出无法直接恢复的备份，需要统一策略。
4. 内容备份没有账号与会话，恢复照片会归恢复账号所有；并非整个原系统的无损迁移。
5. 主要页面仍集中在 `App.vue`，路由目前是占位组件加条件展示，尚未拆成实际页面组件；后端也还可继续拆业务层与数据访问层。
6. Docker 配置已提供并校验语法，但没有完成容器实际构建和容器内端到端验收。

## 建议后续顺序

1. **回忆／相册实体与多图关联**：保留每张照片的日期和 GPS，同时允许同一条回忆拥有多张照片；完成封面、图片顺序和 1／4／9 宫格。
2. **以浏览为主的详情与事件级时间轴**：多图连续查看，编辑作为独立操作，恢复原版最直接的照片体验。
3. **地点搜索与自动归类**：逆地理编码、省／市／地点结构和原始 GPS，避免同一城市因手填名称不同被拆开。
4. **3D 地球与城市点亮**：迁移原版最显著的视觉模块；外部地图数据和依赖仍需实际验证。
5. **情侣专属内容**：恋爱起始日、纪念日、手账、心愿和时光胶囊。
6. **数据与规模能力**：旧数据迁移、统一备份上限、缩略图、分页、存储适配，再按需要补其他工具。

如果目标仍是“两个人按时间／地点收藏照片”，优先完成 1–3 及必要的数据保障；如果目标是完整复刻原版，则需要将上述未迁移模块逐个纳入范围。
